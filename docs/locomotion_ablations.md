# Locomotion Gait Ablations

The current gait study has two source recipes:

- `experiments/train/locomotion_gait_base.yaml` is the retained control. It
  combines the stable PPO settings, positive-biped air time, and pelvis-frame
  stance-width band that survived the previous three-seed study.
- `experiments/train/locomotion_gait.yaml` is the full anti-chatter candidate.
  It adds 40 ms contact debounce, a 1.0 s phase clock, gait-contact reward
  `0.35`, premature-transition penalty `-0.10`, scheduled swing velocity
  `0.25`, and stance-foot slip penalty `-0.05`.

Older one-file-per-treatment `locomotion_clean_*` recipes were removed. All
new single-variable conditions are explicit Hydra overrides generated by
`scripts/run_locomotion_ablation.sh`; this keeps the control inheritance fixed
while making the actual treatment visible in the launch command and W&B config.

## Contact and cadence semantics

The candidate requires a raw contact state to remain changed for `0.04 s`
before accepting a touchdown or liftoff. Accepted transitions update all
contact-dependent rewards, foot-duration memory, and diagnostics.

`contact_timing` is an event penalty rather than a continuous occupancy term.
On touchdown it penalizes the squared normalized shortfall below
`min_air_time`; on liftoff it penalizes the corresponding shortfall below
`min_contact_time`. Mature transitions receive zero. The term is gated out for
linear command speeds at or below `command_speed_threshold` and is not
multiplied by the control timestep.

The full candidate uses:

```text
cycle frequency = clip(1 / 1.0 + 0.15 * command_speed, 0.75, 1.10)
duty factor     = 0.60
fixed command   = 0.30 m/s
cycle frequency = 1.045 Hz
target combined touchdown rate = 2.09 footfalls/s
minimum air/contact duration    = 0.20 / 0.30 s
```

Training reports actual and premature transition rates under:

```text
train/gait/footfalls_per_second
train/gait/liftoffs_per_second
train/gait/premature_touchdowns_per_second
train/gait/premature_liftoffs_per_second
train/mean_reward/contact_timing
```

## One run

List available conditions:

```bash
scripts/run_locomotion_ablation.sh --list
```

Run one local seed for 1,536 updates:

```bash
scripts/run_locomotion_ablation.sh local timing_10 0
```

Override the budget or any Hydra field without editing a recipe:

```bash
TOTAL_TIMESTEPS=25165824 \
scripts/run_locomotion_ablation.sh local clock_swing_025 1 \
  reward_config.swing_foot_velocity.std=0.20
```

Run one Vast seed:

```bash
BRANCH=agent/clean-locomotion-ablation MAX_PRICE=1.25 \
scripts/run_locomotion_ablation.sh vast full_low 0
```

The Vast command trains only the committed remote branch. Commit and push
recipe or implementation changes before launching it.

## Parallel Vast matrix

Launch all 15 conditions for seeds `0`, `1`, and `2` in six parallel tmux
lanes:

```bash
MAX_PARALLEL=6 MAX_PRICE=1.25 \
scripts/run_vast_locomotion_ablations.sh agent/clean-locomotion-ablation
```

Each lane has a detached Git worktree and therefore an independent Vast lock,
active-instance record, and teardown lifecycle. Lanes are parallel; jobs within
one lane are sequential. The launcher prints the tmux window and persistent
status-log paths.

Run a focused matrix by selecting conditions and seeds:

```bash
CONDITIONS="base debounce_04 timing_10 clock clock_swing_025 full_low" \
SEEDS="0 1 2 3 4" MAX_PARALLEL=6 \
scripts/run_vast_locomotion_ablations.sh agent/clean-locomotion-ablation
```

The matrix runner writes every intended job to `manifest.tsv` and every final
exit status to `results.tsv`. Each lane retries failed launches up to
`MAX_ATTEMPTS` (default `3`); child launchers read from `/dev/null`, so they
cannot consume the lane queue from standard input.

The default conditions isolate:

```text
base
debounce_03 / debounce_04 / debounce_05
timing_05 / timing_10 / timing_20
slip_005 / slip_010
clock
clock_swing_025 / clock_swing_050
clock_timing
full_low / full_high
```

## Promotion gates

Compare the final 128 training updates and deterministic checkpoint rollouts.
Do not rank different rewards by total return alone. A candidate advances only
when its multi-seed median preserves at least 900 of 1,000 rollout steps and:

- remains finite with no nonfinite PPO update;
- tracks the fixed `0.30 m/s` command comparably to `base`;
- reduces both actual and premature transition rates;
- approaches the `[0.24, 0.34] m` stance-width band;
- avoids visible foot sliding, crouched recovery, and contact chatter;
- does not exchange lower cadence for more terminal failures.

Evaluate at least three training seeds. The standard training video uses one
deterministic initial state, so full video survival alone is not evidence of
robustness; use randomized evaluation resets before promotion.
